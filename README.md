# CNC Electric Knowledge Bot

Закрытый Telegram-бот для сотрудников CNC Russia. Отвечает на технические, коммерческие и логистические вопросы по каталогам, снимкам 1С и загруженным документам.

**Для кого:** 5 менеджеров, инженер, администратор — плюс клиенты, подписанные на канал [@cncelectric_russia](https://t.me/cncelectric_russia): им бот показывает характеристики, цену и документы, но не склад.

> Границы системы, роли, приоритет источников и список отложенного — в [ARCHITECTURE.md](ARCHITECTURE.md).
> Состав выгрузки счетов из 1С — в [docs/1C_EXPORT.md](docs/1C_EXPORT.md).
> Состав файла со ссылками на фото/паспорта/РЭ/3D/сертификаты — в [docs/MEDIA_LINKS.md](docs/MEDIA_LINKS.md).

> 🔒 **Счета временно заблокированы.** 1С-отдел не даёт доступ к отчёту по
> счетам до демонстрации ценности бота на реальных сотрудниках. Каталог,
> цены, остатки и технические вопросы этого не требуют и работают уже
> сейчас — см. «Ближайший план» ниже.

## Что умеет

**Каталог и склад** (работает)
- поиск товаров по типу, серии, току, полюсам, Icu;
- характеристики по артикулу;
- цена, свободный остаток, товар в пути и дата ближайшего прихода.

**Счета** (🔒 заблокировано — 1С не даёт доступ до пилота, см. выше)
- статус оплаты и отгрузки по номеру счёта или контрагенту;
- построчно: что отгружено, что на складе, что в пути;
- Excel-выгрузка счетов за период.

**Документы**
- ответы по загруженным каталогам, паспортам, инструкциям с указанием источника;
- локальный точный поиск табличных значений по серии;
- честное «подтверждённого ответа нет» вместо догадки.

**Клиенты** (работает)
- ответы о компании, условиях покупки, гарантии, сроках и рекламации;
- вопрос без подтверждённого ответа передаётся в техслужбу с номером —
  ответ инженера возвращается клиенту в тот же чат;
- коммерческий вопрос уходит менеджеру по региону, менеджер получает
  уведомление.

Порядок работы инженера с вопросами клиентов — [docs/ENGINEER_ESCALATION.md](docs/ENGINEER_ESCALATION.md).

**Общее**
- роль пользователя определяется по Telegram ID из `.env`;
- 👍/👎 под каждым ответом;
- каждый ответ несёт источник и дату актуальности данных;
- **внешний ИИ отключён — бот работает только на локальных данных, без интернета.** Переформулированные вопросы («во сколько обойдётся» вместо «цена») ловит локальный поиск по смыслу поверх справочника (`semantic_reference.py` + `reference_lookup.py`); поиск по документам полностью локальный (`knowledge_matrix.py`); всё, чего в базе знаний нет, честно уходит специалисту, а не «выдумывается».

## Чего пока НЕ умеет

Список честный — чтобы не было ложных ожиданий.

| Ограничение | Последствие |
|---|---|
| Данные по счетам обновляются **вручную** (загрузка XLSX) | статус может быть вчерашним — бот предупреждает об этом |
| Дата прихода известна **по артикулу**, не по счёту | нельзя обещать клиенту «ваш товар придёт 05.04», распределение партии — за менеджером |
| Нет доступа для клиентов | менеджер пересылает ответ клиенту сам |
| Нет расчёта селективности и подбора схем | это работа инженера |
| Бот только читает 1С | заказы и документы оформляются в 1С |
| Скидки контрагентов пока не подключены | цена показывается базовая |
| Один язык — русский | экспортные рынки за гейтом |
| Нет очереди разбора расхождений | при конфликте каталога и паспорта бот предупреждает в ответе |
| Не заменяет паспорт изделия | критичные характеристики сверять с паспортом |

## Установка

Требуется Python 3.11+. Внешний ИИ и ключи Anthropic **больше не нужны** —
бот работает полностью локально.

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Затем откройте `.env` и заполните.

### Поиск по смыслу (необязательно, но рекомендуется)

Чтобы бот понимал переформулированные вопросы (клиент спросил другими
словами, не по шаблону), поставьте необязательный слой поиска по смыслу:

```powershell
pip install -r requirements-semantic.txt
```

При первом свободном вопросе бот один раз скачает небольшую русскоязычную
модель (~220 МБ) и дальше работает офлайн. Без этой установки бот тоже
отвечает — но переформулировки ловит хуже (только поиск по словам).
Проверить, включился ли поиск по смыслу, — командой `/status`. Порог
срабатывания настраивается переменной `REFERENCE_SEMANTIC_THRESHOLD`
(по умолчанию 0.72), модель — `REFERENCE_SEMANTIC_MODEL`.

### Распознавание паспортов-картинок (OCR, необязательно)

Часть паспортов и каталогов CNC сделаны в CorelDRAW и сохранены как
картинки — из них не извлекается текст, и без OCR они в базу знаний не
попадут. Чтобы такой массив всё же загрузить:

```powershell
pip install -r requirements-ocr.txt
```

Дополнительно нужен сам Tesseract в системе (Windows-установщик и языковой
пакет **Russian** — ссылки в `requirements-ocr.txt`). **PATH настраивать не
нужно** — бот сам находит `tesseract.exe` в стандартной папке
`C:\Program Files\Tesseract-OCR`; если он установлен в другое место, укажите
путь в `.env`: `TESSERACT_CMD=C:\...\tesseract.exe`. После этого при загрузке
PDF, из которого не извлёкся текст, страница автоматически распознаётся.
Проверить готовность: `python -c "import ocr; print(ocr.available())"`
(должно быть `True`).

⚠️ ЧИСЛА из OCR ненадёжны (колонки таблиц «съезжают»): OCR-текст идёт в
поиск как справочная проза, а точные характеристики бот берёт из 1С, не из
распознанной картинки. Настройки: `OCR_LANG` (по умолч. `rus+eng`),
`OCR_DPI` (300).

### Поиск по смыслу по всему массиву документов

Когда паспорта и каталоги загружены (с OCR или без), на свободный вопрос
бот находит самый близкий по смыслу **абзац** из документов и отдаёт его
дословно — с источником («Паспорт CJX2-D, стр. 4») и оговоркой «сверьте
критичные числа с паспортом». Это финальный резерв на месте убранного
внешнего ИИ: бот цитирует ваш реальный текст, ничего не генерируя, а если
подходящего абзаца нет — вопрос уходит специалисту.

Требует того же слоя поиска по смыслу (`requirements-semantic.txt`). Индекс
абзацев строится один раз после загрузки документов и кэшируется
(`data/document_embeddings.npz`). Порог — `REFERENCE_DOC_THRESHOLD` (0.55);
подобрать по реальным данным поможет `python semantic_probe.py --docs "вопрос"`.

### Массовая загрузка документов

Грузить сотни паспортов по одному через Telegram незачем — есть пакетный
загрузчик целой папки:

```powershell
python bulk_ingest.py "C:\путь\к\папке\с\паспортами"
```

Рекурсивно берёт PDF/DOCX/TXT/MD/CSV/XLSX, распознаёт картиночные PDF (если
установлен OCR), устойчив к битым файлам (один сбой не рушит прогон) и в
конце один раз пересобирает индекс и прогревает эмбеддинги. OCR тяжёлый
(~3–5 с/страница) — сотни паспортов считаются часы, лучше на VPS.

## Конфигурация `.env`

Полный шаблон — файл [.env.example](.env.example) в корне репозитория; «Установка»
выше уже копирует его в `.env`. Ключи в разделах «Счета» и «Поведение» там
помечены как зарезервированные: код их пока не читает — функция ещё не
написана (см. «Ближайший план» ниже), не только заблокирована доступом 1С.

Заполнить обязательно: `TELEGRAM_BOT_TOKEN` (у [@BotFather](https://t.me/BotFather)), `ADMIN_USER_IDS` (ваш ID), логин и пароль 1С. `ANTHROPIC_API_KEY` больше не требуется — внешний ИИ отключён.

Для писем в техслужбу: `SMTP_USER` и `SMTP_PASSWORD` (для Mail.ru для бизнеса — «пароль для внешнего приложения»), `SUPPORT_EMAIL`. Без них вопрос клиента всё равно дойдёт до инженера в Telegram — не будет только письменного следа.

**Подставьте свои значения** вместо примеров: `ANTHROPIC_MODEL` — фактическую модель из кода; `ANALYTICS_RETENTION_DAYS` — срок, согласованный с юристами.

Пароль 1С не должен попадать в исходный код, Git или сообщения.

## Роли

Роль определяется по Telegram ID при каждом сообщении. Подключение сотрудника = добавить ID в `.env` и перезапустить бота.

Клиента подключать не нужно: он им становится сам, подписавшись на канал. Чтобы это
работало, **бот должен быть администратором канала** — иначе Telegram не даёт проверить
подписку, и клиенты получают отказ (в логах — предупреждение об этом).

| Роль | Кто | Доступ |
|---|---|---|
| `admin` | вы | всё, включая бэкапы и синхронизацию |
| `engineer` | инженер | документы, `/reindex`, неотвеченные вопросы, каталог |
| `manager` | 5 менеджеров | каталог, цены, остатки, **все счета компании**, Excel |
| `client` | подписчики канала CNC Electric | артикул, характеристики, цена, аксессуары, паспорт. Вместо остатка и даты прихода — «уточните у менеджера» |
| — | все остальные | приглашение подписаться на канал + свой Telegram ID |

Менеджеры видят **все** счета компании — фильтра «только свои клиенты» нет: отдел один, менеджеры пересекаются и подменяют друг друга. Если политика изменится, переключается `MANAGER_SEES_ALL_INVOICES`.

## Тесты

```powershell
pip install -r requirements-dev.txt
pytest
```

`tests/golden_set.yaml` — прогон роутера на эталонных вопросах (§10
ARCHITECTURE.md); см. предупреждение в начале файла про источник вопросов.

### Два уровня проверки — не путать

Тесты проходят в двух разных условиях, и «зелено» значит в них разное.

| Где | Условия | Что проверено | Что это доказывает |
|---|---|---|---|
| Облачная сессия, CI, свежая копия репозитория | `data/` и `uploads/` отсутствуют — они в `.gitignore` | логика: роутер, лексикон, парсеры, разбор прайс-листа | код не сломан |
| Машина со снимком каталога | `data/api_exports/products.json` на месте | всё то же **плюс** `golden_set` на реальных числах | **Гейт §14 пройден** |

Без снимка каталога `tests/test_golden_set.py` пропускается целиком — не по
одному кейсу, а весь набор. Это сделано намеренно: golden set — измерительный
прибор для критерия «ошибки в числах: 0», и частичный прогон, показанный
зелёным, создавал бы ложную уверенность, что порог взят.

Практически: правку логики можно принимать по первому уровню, а **решение о
готовности к пилоту — только по второму**.

## Ежедневный порядок работы со счетами

> 🔒 Пока не действует: `/upload_invoices` и весь раздел ниже — план на
> момент, когда 1С даст доступ к отчёту (см. «Ближайший план» выше). Сейчас
> этой команды в боте нет.

Когда блокировка снята, действует План А — выгрузка вручную. Достаточно одного раза утром, делает любой менеджер.

1. В 1С открыть отчёт по счетам с детализацией до номенклатуры за нужный период.
2. `Файл → Сохранить как → Лист Excel (.xlsx)`.
3. Отправить файл боту с командой `/upload_invoices`.
4. Бот проверит колонки, перезапишет данные и ответит: сколько счетов и строк загружено, на какую дату.

Дальше все менеджеры пользуются свежими данными. Если выгрузка старше 24 часов, бот сам предупредит в каждом ответе по счетам.

Состав колонок и проверка перед первым запуском — в [docs/1C_EXPORT.md](docs/1C_EXPORT.md).

## Откуда какие данные

| Данные | Источник | Когда обновляются |
|---|---|---|
| Товары, характеристики | API 1С → `products.json` | автоматически 06:00 МСК |
| Совместимость аксессуаров, типоразмер (доп. к API) | прайс-лист CNC (xlsx) | вручную, `/upload_pricelist` |
| Цены | API 1С → `prices.json` | по кнопке |
| Остатки | API 1С → `stock-balances.json` | по кнопке |
| Товар в пути, дата прихода | API 1С → `goods-in-transit.json` | по кнопке |
| Счета, оплата, отгрузка | выгрузка XLSX из 1С | вручную, `/upload_invoices` |
| Технические характеристики | каталоги и паспорта в `uploads/` | при загрузке файла |
| Ссылки на паспорта по сериям | таблица «Серия → паспорт» (xlsx) | вручную, `/upload_passports` |
| Фото и сертификаты по артикулам | таблица номенклатуры (xlsx) | вручную, `/upload_media` |
| Переформулированные свободные вопросы | локальный поиск по смыслу поверх справочника (`semantic_reference.py`) | при правке справочника |

**Бот не учит сам себя.** Ответ Claude на свободный вопрос показывается
пользователю сразу, но в базу знаний **не** попадает: он встаёт в очередь
`/review`, и только явное `/approve` инженером делает его частью базы.
Иначе одна ошибка модели закрепилась бы как подтверждённый факт и
переиспользовалась в следующих ответах. Одобренные ответы подписываются
как «ответ ИИ, проверенный инженером» — не как ответ технической службы CNC.

Обычный вопрос пользователя **не** запускает сетевую синхронизацию — это защищает 1С и ускоряет ответы. Приоритет источников при расхождениях описан в [ARCHITECTURE.md, §5](ARCHITECTURE.md).

## Как задавать вопросы

| Нужно | Пример | Что использует бот |
|---|---|---|
| Точные данные по товару | `Артикул: YCB9-63-1P-C16` | снимок 1С |
| Подобрать товар | `выключатель в литом корпусе` → `1600А` → `3P` → `50кА` | локальный каталог |
| Характеристику серии | `максимальный номинальный ток YCW3` | таблицы каталога |
| Свободный вопрос | `чем YCM3 отличается от YCB9?` | поиск по документам |

Статус счёта (`/invoice 1234`, «счёт 1234 оплачен?») пока не работает — счета
🔒 заблокированы, см. «Ближайший план» ниже.

Опечатки допускаются: `выклчатель в литом корпусе` тоже распознаётся. Контекст фильтров сохраняется отдельно для каждого пользователя и переживает перезапуск бота.

Для актуальной цены и наличия указывайте точный артикул. Без артикула бот отвечает только по базе знаний.

## Что загружать, а что нет

**Загружать:** каталоги, паспорта, инструкции, сертификаты, ваши проверенные ответы.

Давайте файлам понятные имена — они попадут в ссылки на источник: `YCW3_каталог_v3.2_2026.pdf`, `Паспорт_YCM3-250.pdf`, `Проверенные_ответы.md`.

Отдельный файл `Проверенные_ответы.md` с ответами инженера полезен: это самый свежий и надёжный источник.

**Не загружать до появления разграничения прав:** дилерские и контрактные цены, переписку по проектам, персональные данные клиентов, договоры. Поисковый индекс документов пока не различает роли — то, что попало в него, доступно всем сотрудникам с доступом к боту.

## Бэкапы

Ежедневно в 03:00 в `backups/` попадают две разные вещи.

| Что | Как часто | Хранится | Восстановимо иначе? |
|---|---|---|---|
| `bot_*.db` — счета, логи запросов, 👍/👎, неотвеченные | каждый день | 30 дней | нет |
| `uploads_*.zip` — каталоги, паспорта, прайс-листы | **только когда состав `uploads/` изменился** | 5 последних архивов | **нет** |

Про архив `uploads/`: `data/knowledge.db` пересобирается из этих файлов
командой `/reindex`, а сами файлы — ниоткуда. Поэтому бэкапится источник, а не
производный индекс. Архив создаётся, только если изменился состав каталога
(сверяется отпечаток «имя + размер + время» в `backups/uploads_last.sha256`) —
57 МБ ежедневно ради файлов, которые меняются раз в месяц, только съедали бы
место.

**Обязательно настройте копирование `backups/` за пределы сервера** — второй диск, облако, локальная машина. И раз в месяц проверяйте, что копия открывается: непроверенный бэкап не считается бэкапом.

## Диагностика

| Симптом | Причина и решение |
|---|---|
| «Бот доступен только сотрудникам» | ID не внесён в `.env` или бот не перезапущен после правки |
| Нет цен и остатков | снимок не создан: нажать «🔄 Обновить цены и наличие», проверить логин/пароль 1С |
| Устаревшие остатки | не прошёл синк 06:00 — проверить логи и уведомление админу |
| «Данные по счетам от …» | нужна свежая выгрузка `/upload_invoices` |
| Ошибка при загрузке счетов | не тот отчёт: нужна детализация до номенклатуры, проверить обязательные колонки |
| Артикул в счёте не связался со складом | формат артикула в выгрузке не совпадает с `vendor_code` в `products.json` |
| Переформулированные вопросы находятся хуже | не установлен поиск по смыслу — `pip install -r requirements-semantic.txt`, проверить через `/status` |
| В снимке HTML вместо JSON | сохранена страница авторизации, а не ответ API |
| Ответ по серии неверный | проверьте, что загружена последняя версия каталога, а не архивная |

**Спринт 2 — счета из 1С (План А),** когда 1С даст доступ: загрузка XLSX, статус по строкам, связь со складом и транзитом.

## Правовые замечания

- Хостинг и база данных — в РФ. `ANALYTICS_RETENTION_DAYS` задаёт срок хранения текста вопросов по политике, но автоматическая очистка `query_log` по этому сроку **пока не реализована в коде** — до реализации старые записи нужно удалять вручную, если требуется.
- Данные счетов и контрагентов **не передаются в Claude (Anthropic)** — обрабатываются только локально. Поиск по документам тоже полностью локальный (`knowledge_matrix.py`), внешнего хранилища документов бот не использует.
- Персональные данные контактных лиц при разборе выгрузки не сохраняются.
- Ответы бота носят справочный характер. Перед передачей клиенту сверяйте критичные характеристики с действующим паспортом изделия, а сроки поставки — с менеджером логистики.
