## 1. План А — ручная выгрузка (сейчас)

Источник: **отчёт по счетам с детализацией до номенклатуры**, а не просто
список счетов — без строк по артикулам бот не сможет связать счёт со
складом и транзитом.

`1С → отчёт → Файл → Сохранить как → Лист Excel (.xlsx) → отправить боту
командой /upload_invoices`.

### Обязательные колонки

**Шапка счёта** (по одной строке на счёт, может повторяться в каждой строке
табличной части — bot.py агрегирует сам):

| Колонка | Поле в БД | Обязательна | Пример |
|---|---|:--:|---|
| Номер счёта | `invoices.number` | да | 1234 |
| Дата счёта | `invoices.date` | да | 12.03.2026 |
| Контрагент | `invoices.counterparty` | да | ООО «Ромашка» |
| Код контрагента (1С) | `invoices.counterparty_code` | нет | 000123 |
| Сумма счёта | `invoices.amount_total` | да | 847300.00 |
| Оплачено | `invoices.amount_paid` | да | 500000.00 |

**Строка табличной части**:

| Колонка | Поле в БД | Обязательна | Пример |
|---|---|:--:|---|
| № строки | `invoice_lines.line_no` | да | 1 |
| Артикул | `invoice_lines.vendor_code` | да | YCB9-63-3P-C25 |
| Наименование | `invoice_lines.name` | да | Выключатель YCB9-63 3P C25 |
| Количество | `invoice_lines.qty` | да | 120 |
| Цена | `invoice_lines.price` | да | 4520.00 |
| Сумма строки | `invoice_lines.amount` | да | 542400.00 |
| Отгружено | `invoice_lines.qty_shipped` | да | 120 |

**Явно НЕ нужны** (§7): колонка «Менеджер» — фильтр «свои клиенты» не
реализуется (§3); колонка «Дата прихода» — берётся из
`goods-in-transit.json` по артикулу, а не из счёта.

### Производные поля

`payment_status` и `shipment_status` бот вычисляет сам при импорте:

```
amount_paid == 0            → payment_status = not_paid
0 < amount_paid < amount_total → payment_status = partial
amount_paid >= amount_total → payment_status = paid

сумма qty_shipped по строкам == 0     → shipment_status = not_shipped
0 < отгружено < заказано (по строкам) → shipment_status = partial
отгружено >= заказано по всем строкам → shipment_status = shipped
```

`snapshot_at` — момент загрузки файла в бот (не дата отчёта в 1С).

## 2. Перед первым запуском — проверить руками

Три открытых вопроса блокируют Спринт 2 (ARCHITECTURE.md §16):

- [ ] **Есть ли в 1С отчёт с детализацией до номенклатуры** (не только шапки
      счетов). Если только шапки — нужен другой отчёт или доработка.
- [ ] **Формат артикула совпадает с `vendor_code` в `products.json`.**
      Взять 10 случайных артикулов из тестовой выгрузки, поискать в
      `data/api_exports/products.json`. Если формат отличается (пробелы,
      регистр, дефисы) — без нормализации связка со складом и транзитом не
      заработает вообще.
- [ ] **Суммы с НДС или без.** Один раз зафиксировать и не менять молча —
      от этого зависит, что именно видит менеджер в ответе бота.
- [ ] Согласовать с юристами формулировку «долг»/«дебиторка» —
      `SHOW_DEBT_WORDING` в `.env`.

Если пункт не выполнен — писать код `orders/importer.py` рано: он будет
парсить то, чего в реальности нет.

## 3. План Б — автоматизация (позже, по триггеру)

Когда переходим (ARCHITECTURE.md §7): менеджеры пользуются счетами через
бот ежедневно 3+ недели **и** ручная выгрузка регулярно забывается/задерживается.

Регламентное задание 1С раз в 15 минут пишет `invoices.json` (тот же состав
полей, что в разделе 1) в папку на диске. `INVOICES_JSON_PATH` в `.env`
указывает на неё. Бот читает файл вместо `/upload_invoices`. Формат данных
не меняется — меняется только источник; `orders/importer.py` не переписывается,
только точка входа.

### ТЗ для 1С-специалиста (набросок, ~2 страницы после уточнения раздела 2)

1. Регламентное задание, периодичность 15 минут.
2. Источник — тот же отчёт, что и в Плане А (или его программный аналог).
3. Выгрузка в JSON со структурой `{"invoices": [...], "generated_at": "..."}`,
   поля — как в таблицах раздела 1 (snake_case).
4. Запись атомарная: во временный файл, затем переименование — недописанный
   файл не должен попадаться боту на чтении.
5. Ошибка формирования не должна затирать предыдущий валидный файл.

Финальный вариант ТЗ пишется после того, как пункты раздела 2 закрыты и
демо на Плане А отработало — просить «автоматизировать то, что уже
работает» намного легче, чем абстрактную интеграцию (§7).
