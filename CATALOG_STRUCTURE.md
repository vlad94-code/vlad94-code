# Структура товарной номенклатуры CNC Electric (из прайс-листа V3.8, 28.07.2026)

Документ описывает реальную структуру официального прайс-листа и нормализованную
модель данных, в которую он преобразован скриптом `parse_price_list.py` →
`products_matrix.json`. Это основа для переработки CATALOG-модуля бота
(`catalog_search.py`, `knowledge_matrix.py`).

## 1. Категории оборудования = листы файла

| Лист Excel | Код (префикс артикула) | Категория | Активных позиций |
|---|---|---|---|
| A (модульное) | A | Модульное оборудование | 4551 |
| B(силовое) | B | Силовое оборудование | 3523 |
| С(коммутация) | C | Коммутационное оборудование | 1166 |
| EN (DC) | EN | Оборудование постоянного тока | 1029 |
| D (реле) | D | Реле | 15 |
| E (светосигн) | E | Светосигнальная аппаратура | 1231 |
| F(блоки питания) | F | Оборудование электропитания | 83 |
| G (измерительное оборудование) | G | Измерительные устройства и датчики | 279 |
| **Выведено из ассортимента** | (разные) | снятые с производства позиции | 6570 |

**Итого активных: 11 715 SKU** + 6570 архивных = 18 447 строк в объединённой матрице.

Префикс артикула однозначно определяет категорию (`A033061` → модульное,
`B050001` → силовое и т.д.) — это можно использовать для быстрой маршрутизации
запроса без полнотекстового поиска, если пользователь называет артикул.

⚠️ Важно: в архивном листе есть категория **`H` — "Электрические аксессуары"**
(кабельные наконечники, клеммники, термоусадка, розетки, кримперы и т.д.,
3753 позиции), которой **больше нет ни на одном активном листе** — этот товар
полностью выведен из ассортимента компании, не просто "устаревшая серия".

## 2. Общие поля (есть на каждом листе)

| Поле в Excel | Поле в JSON | Комментарий |
|---|---|---|
| Артикул | `article` | уникальный ключ |
| Тип | `type` | тип товара внутри категории, напр. "Диф. автомат" |
| Описание | `name` | полное наименование с параметрами |
| Цена с ДД.ММ.ГГГГ, руб. с НДС | `price` / `price_date` | дата зашита в заголовок колонки, распарсена |
| Серия | `series` | напр. YCB9-80M |
| Типоразмер | `size` | заполнено не всегда (частично: A, B, EN, C, G) |
| Категория оборудования | `category_name` | дублирует лист, оставлено для проверки |
| Габариты коробки(см) | `specs.box_dims_cm` | напр. 43*29*25 |
| Вес брутто (кг) | `specs.weight_kg_gross` | |
| Кратность упаковки (шт) | `specs.pack_multiplicity` | |

## 3. Аксессуары/принадлежности — это строки внутри тех же листов

Отдельного листа под аксессуары нет. Аксессуар — это обычная строка, у которой:

- `Тип` = "Принадлежности к ... оборудованию" (или "Принадлежность" на листе E)
- колонка **"Аксессуары"** заполнена — содержит вид аксессуара
  (13 видов на листе A: расцепитель минимального напряжения, независимый
  расцепитель, дополнительный контакт, аварийный контакт, моторный привод,
  выносная поворотная рукоять, блокировка, модуль WiFi и т.п.)
- колонка **"Серия"** содержит список **совместимых серий** через `/`,
  например `YCB9-80M/YCB9-80M DB/YCB9LE-80M/YCB9HL-63/YCB9-63R`

В нормализованной модели это отражено полями:
```json
"is_accessory": true,
"accessory_kind": "Независимый расцепитель",
"compatible_series": ["YCB9-80M", "YCB9-80M DB", "YCB9LE-80M", "YCB9HL-63", "YCB9-63R"]
```
Всего в файле 1074 позиции-аксессуара — их стоит искать/показывать при
запросе "что можно докупить к YCB9-80M", а не хранить отдельно от товаров.

## 4. Специфичные характеристики — разные по категориям, идут в `specs{}`

Общая схема одна, но набор технических полей у каждой категории свой
(поэтому единая плоская таблица с фиксированными колонками не подходит —
нужен `specs` как словарь "что есть, то есть"):

- **A (модульное)**: Ном. ток In(А), Кол-о полюсов, Icu(кА), IΔn(мА),
  Характеристика срабатывания (B/C/D), Тип тока утечки, Тип расцепителя,
  Напряжение катушки, счётчики контактов НЗ/НО (силовых и вспомогательных)
- **B (силовое)**: то же + Класс отключающей способности, Тип предохранителя,
  Исполнение
- **C (коммутация)**: Мощность (кВт), контакты НЗ/НО (для контакторов/пускателей)
- **EN (DC)**: Напряжение (для DC), параметры рубильника (блокировка, монтаж,
  схема подключения, тип корпуса)
- **D (реле)**: Ном. напряжение
- **E (светосигнальная)**: Подтип, Цвет, форма, число положений переключения,
  степень защиты, доп. опции (подсветка, запирание, влагозащита и т.д.)
- **F (блоки питания)**: Мощность, Фазы, Входное/выходное напряжение
- **G (измерительное)**: Подтип, режим индикации, коэффициент трансформации,
  класс точности, мощность (ВА/кВар)

## 5. Статус позиции — 3 состояния

Определяется не отдельной колонкой, а **заливкой ячейки артикула**:

| status | Как определяется |
|---|---|
| `active` | обычная строка на активном листе |
| `discontinued_in_stock` | строка на активном листе с заливкой `FF0070C0` (синий) — снято с производства, но остаток есть на складе (162 позиции по всем листам) |
| `discontinued` | строка на листе "Выведено из ассортимента" (6570 позиций) |

Примечание на листе "Главная" прямо подтверждает эту логику ("выделено синим —
оборудование, которое снято с производства, но есть в наличии на складе").

## 6. Известные проблемы качества данных в самом прайс-листе

- В листе "Выведено из ассортимента" **151 строка дублируется**
  один в один (одинаковый артикул, наименование, цена) — это дубли в
  исходнике, не ошибка парсинга. При индексации стоит де-дублировать по
  артикулу.
- 162 артикула встречаются и на активном листе, и в архиве одновременно
  (видимо, товар то снимался, то возвращался в номенклатуру) — при построении
  индекса активная версия должна иметь приоритет.

## 7. Как это ложится на бот

Для `catalog_search.py`/`knowledge_matrix.py` предлагается:

1. Генерировать `products_matrix.json` этим скриптом при каждом обновлении
   прайс-листа (сейчас `data/api_exports/products.json` из 1С — судя по всему
   именно рассинхронизация схемы полей с тем, что ожидает `catalog_search.py`,
   и есть причина бага "ничего не найдено").
2. Индексировать в FTS одновременно: `article`, `name`, `type`, `series`,
   `specs` (сплющенные в текст) — это покрывает и точный поиск по артикулу,
   и поиск по параметрам ("автомат 32А 3П").
3. При ответе про товар сразу подтягивать связанные аксессуары —
   `compatible_series` содержит серию, значит достаточно матчить
   `product.series in accessory.compatible_series`.
4. Отдельно обрабатывать `status`: по умолчанию показывать только `active` +
   `discontinued_in_stock` (то, что реально можно купить сейчас), архивные —
   только если явно спросили "было ли у нас..." или похожий товар не нашёлся
   среди активных.
